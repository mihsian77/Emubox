# EmuBox UI 排版规格 v1

> 状态：信息架构已定案（2026-11-07）。视觉方案 A「璃光暗夜」。
> 本文只管**排版与信息架构**，颜色见 `ui/theme/Color.kt`。

## 一、一级导航：4 个 tab

| tab | 装什么 | 对应旧分区 |
|---|---|---|
| 首页 | 设备结论、今日更新、快捷入口 | DEVICE |
| 模拟器 | 应用库、排行、兼容性 | EMULATORS |
| 驱动 | 驱动 + 组件，页内二级分段切换 | DRIVERS + COMPONENTS |
| 运行库 | Visual C++ / .NET / 运行环境 | RUNTIME |

**移出一级导航的**：下载、设置、指南 → 收进右上角「我的」入口。
理由：三者都是低频或瞬态功能，占一级位置挤掉的是高频入口。

**旧路由不做删除**：`AppScreen` 枚举保留 8 项，`when(currentScreen)` 分发不动，
只改底部导航的展示项与选中逻辑。这样后台服务、深链、指南返回栈全部不受影响。

### 选中态规则

- `DEVICE` → 高亮「首页」
- `EMULATORS` → 高亮「模拟器」
- `DRIVERS` / `COMPONENTS` → 高亮「驱动」
- `RUNTIME` → 高亮「运行库」
- `DOWNLOADS` / `SETTINGS` / `GUIDE` → 不高亮任何 tab（它们是二级页）

## 二、三类页面模板

8 个分区收敛成 3 套骨架。新页面只能往这三套里填，不准另起一套。

### A. 列表型（模拟器 / 驱动 / 组件 / 运行库）

```
┌ 顶栏：标题 · 右侧「我的」
├ 搜索条（吸顶，滚动时保留）
├ 筛选 chips（单行横向，最多 5 个 + 「更多」）
├ 排序行（左「N 个结果」右「排序 ▾」）
└ 列表（卡片，首屏 ≥ 2 条）
```

硬性要求：
- 首屏必须露出 **≥ 2 条真实结果**。
- 说明性长文案（如「常用安卓模拟器汇总…」）收进标题旁的 ⓘ，不占列表空间。
- 榜单/推荐位**最多 1 个**，且推荐过的条目在列表中标记「已推荐」不再重复展示。

### B. 详情型（设备 / 驱动详情）

```
┌ 顶栏：返回 · 标题
├ 结论卡：一句话说清「你这台能跑什么」
├ 关键参数（3–4 项，单行横排，不做大格子）
├ 分组列表（每组一个标题 + 若干行）
└ 底部固定操作条（下载 / 应用）
```

硬性要求：
- **结论在参数之前**。用户要的是判断，不是跑分。
- 参数用紧凑两列，不用一张卡只放 1 个值。
- 不在详情页塞资讯流。

### C. 设置型（设置 / 下载 / 指南）

```
┌ 顶栏：返回 · 标题
├ 分组标题（小字、弱色）
├ 行：左标题+副标题 / 右控件
└ 分组间距 24dp，行高 ≥ 56dp
```

硬性要求：一个分组不超过 8 行；超过就再分组。

## 三、五条硬规则（验收用）

1. **首屏见内容**：列表页首屏至少 2 条真实结果。控件、说明、推荐位不得把它挤出屏。
2. **控件不过三**：搜索 + 一组筛选 + 排序。第四层控件一律进「更多」。
3. **卡片不套娃**：一张卡内最多一层底色变化。层级靠间距、字重、描边区分，不靠叠背景色。
4. **一屏一任务**：设备页不放新闻，列表页不放长说明，详情页不放推荐位。
5. **不重复展示**：同一条目在同一屏只出现一次（推荐位与列表二选一）。

## 四、验收方式

不靠肉眼。用现成的 Roborazzi 截图测试：

```bash
./gradlew :app:testDebugUnitTest --tests "*ScreenRenderTest" -Dscreenshot.dir=build/screenshots
```

产出 PNG 后逐条对照上面五条规则。改版前后各跑一次，同机位并排比对。

## 六、模板组件库

`app/src/main/java/com/emubox/app/ui/template/PageTemplates.kt`

| 组件 | 用途 | 强制约束 |
|---|---|---|
| `listPageHeader` | 列表页头部一次给齐标题/上下文/搜索/筛选/计数 | 顺序固定，不接受调参；控件不超过三层 |
| `PageTitleRow` | 标题 + 可选副标题 + 可选图标 | 副标题单行截断 |
| `FusionSearchBar` | 搜索条 | 渐变底（纯色在深色底上看不出边界）+ 有内容才出清空键 |
| `FilterChipRow` | 一行筛选 | 横向滚动，永不换行 |
| `ResultCountRow` | 结果计数 | 列表页必须有且只出现一次 |
| `CollapseRow` | 折叠区入口 | 次要内容默认收起 |
| `FusionCard` | 卡片外壳 | 一层底色 + 一层描边，内部禁止再叠底色 |
| `ConclusionCard` | 详情页结论卡 | 结论在参数之前，主操作最多一个 |
| `SpecStrip` | 关键参数横排 | 3–4 项一行，不换行、不做大格子 |
| `FactRow` | 详情页键值行 | 标签固定宽，值可换行 |
| `DetailActionBar` | 详情页底部固定条 | 放进 bottomBar，主按钮只放一个 |
| `SectionHeader` | 分组标题 | 小字 + 弱色，替代带图标盒的大标题 |
| `SettingGroup` | 设置分组容器 | 一组一卡，组内不超过 8 行 |
| `SettingRow` | 设置行 | 左标题/副标题，右控件，行高 ≥ 56dp |
| `SettingChoiceRow` | 选择型设置行 | 控件独占一行（chips / 分段 / 下拉） |

### 两个写页面时一定会踩的坑

1. **`LazyListScope` 扩展不是 `@Composable` 上下文。** 在 `LazyColumn { ... }` 里不能调 `appString()`，文案必须在页面函数体先取成变量。
2. **`item {}` 不能塞进 `Column`。** 折叠区不能写成「一个 item 里放 CollapseRow + Column 包住其他内容的 item」，必须把展开态提升到页面级，用 `if (expanded) { item {} ... }`。
